# SDD Slidev 第二轮视觉审计

> 审计基准：1600 × 900 最终 click 状态  
> 设计方向：工程蓝图 / 信号路径，而不是 UI 卡片墙

## 1. 演示的传播任务

听众是已经开始使用 Agent 的开发团队。演示结束时，他们应当能把 SDD 理解为一套从意图、执行到证据和组织复用的控制系统，而不只是“先写一份 Spec”。

## 2. 当前问题

1. `SlideShell` 被正式稿样式从绝对定位改成内容高度，页脚停在内容之后，造成系统性的下半页空白。
2. 40 页中的大多数页面使用同一种“顶部标题 + 横向卡片列”轮廓，相邻页缺少节奏变化。
3. 部分图形只是把名词装进盒子，没有用位置、大小、方向和连接关系解释因果或约束。
4. 卡片、圆角和标签过多，整体更像后台 UI，而不像面对观众的技术演示。
5. 页面虽然没有越界，但视觉重心普遍位于画布上方 45% 区域，底部缺少承接。

## 3. 新的构图规则

- 每页只允许一个主构图，其余信息作为注释、轴线或证据附着其上。
- 主体至少占可用内容区高度的 65%；刻意留白页除外。
- 卡片只在内容确实是独立对象或可比较对象时使用。
- 位置表达语义：左→右表示演进，中心→外围表示控制，顶部→底部表示抽象到具体，闭环表示反馈。
- 相邻三页不能连续使用同一种轮廓。
- 页脚固定在画布底部；标题区与主体区分别占约 20% / 68%，其余作为呼吸区。
- 动画用于暴露决策或反馈关系，不逐条播放装饰性内容。

## 4. 六种版式家族

### A · Thesis

大标题或核心结论占 45% 以上画布，配一个视觉锚点。用于转折与章节关键结论。

```text
┌────────────────────────────────────────────┐
│  SECTION                                   │
│  一句真正的结论                            │
│                         ┌──────────────┐   │
│  辅助解释               │  VISUAL KEY  │   │
│                         └──────────────┘   │
└────────────────────────────────────────────┘
```

### B · Signal Path

一条贯穿画面的路径承担主逻辑，节点只保留输入、动作、证据和 Gate。用于流程与方法演进。

### C · Control Field

中心对象与外围约束形成空间关系。用于 Agent、Harness、Spec 协议和 Plugin。

### D · Transformation

左右不对称：问题侧更轻、更碎；目标侧更完整、更有结构。用于 Before/After、Is/Is Not 和反例。

### E · Depth / Layers

垂直深度表达抽象层级、稳定性或组织沉淀。用于知识库、能力栈和成熟度。

### F · Evidence Surface

表格、指标或审查结果占据主体，不再额外叠加装饰卡片。用于 Framework 选择、风险、反例与度量。

## 5. 优先重构页面

| 页码 | 当前问题 | 目标构图 |
| --- | --- | --- |
| 2 | 七张等权卡片，流程没有形成连续运动 | 一条全宽人工交付链 + 责任带 |
| 5 | 左侧栈与右侧四卡缺少因果 | 能力分层作为纵轴，四种外部能力挂接到对应层 |
| 6 | 九宫格像控制台，关系不清 | Agent 核心 + 四个控制域 + 外圈边界 |
| 10 | 主路径和外循环上下堆叠，闭环感弱 | 单一双层闭环路径 |
| 12 | 文档组件与例子都偏小 | 大型 Spec 剖面 + 例子直接标注字段 |
| 18 | 六张实现步骤卡片过于稀疏 | 从 Diff 到 Evidence 的连续证据链 |
| 25–27 | 三个框架页都是横向盒子流水线 | 分别采用 Change 轨道、Constitution Spine、Skill Guardrail |
| 33 | 七张等权卡片，选择逻辑不明显 | 能力漏斗：候选 → 过滤 → 装配 → 运行 → 证据 |
| 40 | 系统图偏小，结尾像产品卡片 | 全宽系统闭环 + 右下角品牌收束 |

其余页面先通过全画布 Shell、垂直居中和页面专属尺度修正配重，再根据第二轮截图决定是否继续重构。

## 6. 实施结果

- 修复 `SlideShell` 画布定位，主体区和页脚重新占满 16:9 安全区。
- 重构第 2、5、6、10、12、18、26、27、33、40 页的主构图。
- 放大 OpenSpec、Spec Kit、Superpowers、Plan、Graph 和度量页的舞台尺度。
- 对早期 AI、Agent、TDD、方法/框架/Harness 等动画页保留低亮度锁定轮廓，避免初始态失重。
- 相邻页面已经形成责任链、控制场、分层、闭环、转换、证据面等不同轮廓。
- 40 页初始态与最终 click 状态均完成 1600 × 900 截图审阅；背景 Glow 之外无可见越界。
